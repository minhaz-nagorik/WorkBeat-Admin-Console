# Admin decisions — A1–A14

Rulings this repository made where Plan v3.5 and the backend specs are silent. Each must agree with
Plan v3.5 and its D-numbers and with the backend's B-numbers; a disagreement is a defect. Cite them
as `A<n>` in specs.

| # | Decision | Why |
|---|---|---|
| A1 | Source order: Plan v3.5, then the backend specs (WorkBeat-Backend `docs/openspec`), then the prototype (`design/reference/workbeat-prototype.html`). The prototype fixes look, layout and wording only; where it contradicts a higher source the higher source is built. Deviations are listed in [design/README.md](../design/README.md) | The prototype predates v3.1–v3.5 in places (MDM, reassign) |
| A2 | The API runs sign-in (`POST /v1/auth/login` returns an opaque 7-day `token`). The app's server keeps it in an httpOnly cookie and makes every API call with it; browser code calls the app's server and never sees the token. The app never touches the database or file storage and holds no API secret | Plan-v3.5 §2.2 and §3 "Web frontend"; no Supabase since 16 Nov 2026 (backend reply 16 Nov 2026, WorkBeat-Backend CLAUDE.md) — amends Plan-v3.5 §2.1 "Auth" |
| A3 | After sign-in the app loads `GET /v1/me` once per session and builds navigation, landing page and page access from `role`. A route the role may not open redirects to the role's landing page | D41; landing pages from the prototype: Overview for company roles, Companies for staff |
| A4 | Every API enum shown to a person (tamper `event_type`, device `status` and `badges`, pause `reason` and `status`, roles, company status) is rendered through one label map in plain language. Raw enum values never reach the screen | Prototype alerts review (16 Nov 2026): "hosts file changed" and "watchdog" are not words customers use |
| A5 | The alerts badge, alerts page, devices list and setup checklist refresh by polling every 30 s while the tab is visible, and stop while it is hidden. Overview does not poll: it loads on open and on Refresh (product owner, 19 Nov 2026), because its dashboard call adds up today's activity for every employee | Backend `alerts-feed`: push is not required, events show within 1 minute when polled every 30 s |
| A6 | Secrets (licence key, uninstall token, new reissued key) are fetched only on an explicit reveal or copy, kept in component memory only, cleared on navigation, never logged, never in a URL, browser storage or analytics. Signed URLs (screenshots, downloads) are used at once and never cached | B6; Plan-v3.5 §5.3 "Secret" |
| A7 | A destructive action asks for confirmation in place (inline confirm, or a dialog when the consequence needs a paragraph) and names its consequence. Nothing destructive is a single click | Prototype `confirmBox`; release and suspend cannot be undone from the portal |
| A8 | Every list has a search box, the filters the page needs and a pager (10 rows by default, 10/25/50). A filter with more than four options is a dropdown | Prototype lists; the alerts filter became a dropdown in the 16 Nov 2026 review |
| A9 | Dates and times are shown in `companies.timezone` (`company.timezone` from `GET /v1/me`), never the browser's zone, with relative wording ("09:42 today", "Yesterday 16:03") for the last two days | B19; a manager in another zone must see the company's day |
| A10 | Stack: Next.js 14+ App Router, TypeScript strict, Tailwind, shadcn/ui, no Supabase (the API owns sign-in), request and response types written from the backend's `docs/core/api/portal-api.md` and `staff-api.md` (the contract; every name is the one the code returns) until the backend publishes `packages/shared`. Deployed on Vercel | Plan-v3.5 §2.1, §3, amended by the 16 Nov 2026 no-Supabase decision |
| A11 | WCAG 2.2 AA: every control has a label, every action is keyboard reachable, focus is visible and returns after a dialog closes, colour is never the only signal (pills carry text), charts have a text alternative | Prototype already does this; never cut |
| A12 | An API error is shown in plain language next to what caused it: field errors (`422 VALIDATION_FAILED` with field names) beside the field, `409` codes as a sentence that says what to do next, `403` as "You don't have access", `401` returns to sign-in, `5xx` and network errors as a retry message. The raw `code` is never shown | Backend `api-envelope`; A4 |
| A13 | No second factor for anyone. Staff (`super_admin`) sign in with email and password, like company users; there is no authenticator set-up, code step or authenticator reset. Decided by the product owner on 16 Nov 2026, waiving the MFA part of Plan-v3.5 D41 and §4.6. | Product owner, 16 Nov 2026; supersedes backend B23 |
| A14 | An IT Admin may add, edit, remove and import employees, change monitoring settings and pauses, release and deactivate devices, resolve alerts and change the block list, private sites and productivity rules, but every such write answers `202 { change }` and applies only when a Company Admin approves it on the Approvals page; a Company Admin's writes apply at once. An IT Admin has no Deployment page (licence key, uninstall token, minimum agent version, setup checklist), only Downloads, and still sees no activity, reports, calendar, timesheets, screenshots or notice acknowledgements | Product owner, 17 Nov 2026; contract in [backend-requests-6.md](../backend-requests-6.md); amends the IT Admin column of `role-access` and B18 |
| A15 | Company settings shows a Company Admin only the time zone and the idle threshold. Company name, data retention, the monitoring notice (editor and template) and billing are not offered to any company role; the API refuses them (backend B29). Staff set name and retention on the staff Companies page. The screenshot interval stays on each employee, never faster than the plan, with the plan read from the employee's monitoring settings | Product owner, 19 Nov 2026; backend B29 |
| A16 | Staff change a company's plan, seat limit, screenshot plan ("Plan and seats", on Companies and Licences) and status ("Status": trial with days, active, suspended, expired) from the staff area. Lowering the screenshot plan, suspending and expiring are confirmed first. Each company row has one Manage button that opens all of these, plus End trial for a trial company | Product owner, 19 Nov 2026; backend B30 |
| A17 | Company settings shows a Company Admin a Custom domain card: add, change or remove the domain, its status and the CNAME and TXT records to create (amends A15). The staff Custom domains page approves or rejects a pending domain after staff check its TXT record by hand, and deactivates an active one (backend B33). The console opens on a custom domain only once it is active; any other unknown address redirects to the main sign-in | Product owner, 22 Nov 2026; backend B33 |
